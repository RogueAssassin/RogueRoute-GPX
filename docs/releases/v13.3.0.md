# rogueroute-gpx v13.3.0 — Map preparation that cannot take the server down

Preparing a very large region (such as the whole United States) could use all of the host's
memory and push it into swap until other services stopped responding. v13.3.0 puts map work
inside firm limits.

## What changed

- **Memory cap.** `./rogueroute-gpx` caps the container at `ROGUEROUTE_MEMORY_LIMIT`: `auto`
  (the default) is 70% of host RAM, or set a size such as `64g`, or `none`. Swap is capped to the
  same value. If the cap is reached, the kernel stops the map tool inside the container; the
  website and `osrm-routed` keep running, and the rest of the host is not affected.
- **Size check.** Each region gets a memory estimate: 5 times the extract size for the foot
  profile (4 for bike, 3 for car), or its measured peak once it has been prepared. A region
  that needs more than 85% of the cap is refused by `osm add`, skipped by auto-prepare and
  `prepare-downloaded`, and marked **Too large for this server** on `/maps`. Add `--force`, or
  use **Prepare anyway** on `/maps`, to try it inside the cap.
- **Memory watchdog.** While a map tool runs, the supervisor checks memory every 2 seconds. It
  stops the tool when free host memory falls below `ROGUEROUTE_MEMORY_FLOOR` (default 5% of
  RAM, at least 2 GB) or the container reaches 95% of its cap, and records why.
- **Gentler on disks.** Map tools run at idle disk priority (`ROGUEROUTE_PREPARE_IDLE_IO=true`)
  as well as low CPU priority, and are the first process the kernel stops if memory runs out.
- **Visible limits.** `./rogueroute-gpx osm status`, `doctor` and `/maps` show the cap, what map
  work may use and each region's estimate. The log records the peak memory of each build.

## Upgrade

```bash
cd /opt/media-server/rogueroute-gpx
./rogueroute-gpx update
./rogueroute-gpx osm status   # check the "Memory:" line and any "too large" regions
```

`update` adds the new settings to `.env` with their defaults. On rootless Podman the cap needs
cgroup v2 with the memory controller delegated to your user, which is the default on current
distributions. See [upgrading](../upgrading.md).
