# rogueroute-gpx v13.0.0

v13 rebuilds the runtime as **one container** and makes region switching automatic. It
replaces the v12 layout of four containers, whose website region switch drove Docker Compose
through the engine socket and kept failing on Podman.

## Highlights

- **One image, one container.** `ghcr.io/rogueassassin/rogueroute-gpx` runs the website,
  OSRM, region switching, and map download and preparation. No manager sidecar, no
  secrets-init, no engine socket, no secrets volume.
- **Region switching without recreating containers.** A small supervisor (PID 1) runs
  `osrm-routed` as a child process and restarts it on another graph. A failed load restores the
  previous region. Docker and Podman behave identically.
- **Automatic regions.** Generating a route picks the prepared region that contains all
  waypoints and loads it if needed. The Map region panel can force a region.
- **Maps managed in the container.** `./rogueroute-gpx osm download|prepare|switch` run inside
  the container with the upstream OSRM tools; the host needs no curl or OSRM image. Optional
  website administration with `ADMIN_TOKEN`.
- **Single region catalog** in `regions.json`, including the areas used for automatic selection.
- **Lowercase naming everywhere:** repository, install path `/opt/media-server/rogueroute-gpx`,
  script `./rogueroute-gpx`, packages `@rogueroute-gpx/*`, IITC plugin
  `rogueroute-gpx.user.js`.
- Built from the official `ghcr.io/project-osrm/osrm-backend:v26.7.3-debian` image (amd64 and
  arm64), with Node 26.8.1 added.

## Upgrading from v12

Follow [upgrading.md](../upgrading.md#from-v12-to-v13). In short:

```bash
git remote set-url origin https://github.com/RogueAssassin/rogueroute-gpx.git
git pull --ff-only
./rogueroute-gpx update
```

Existing prepared maps are reused. Rogue Dashboard needs no changes.

## Removed

- `OSRM_MANAGER_*`, `OSRM_SWITCH_ENABLED`, `CONTAINER_SOCKET`, `OSRM_IMAGE`,
  `OSRM_HOST_PORT`, `OSRM_GRAPH` and `OSRM_PBF` settings (removed from `.env` by `update`).
- The published OSRM port 5000; use `/api/health/osrm` for monitoring.
- `scripts/osm.sh` and `scripts/osm-region-catalog.sh`.
